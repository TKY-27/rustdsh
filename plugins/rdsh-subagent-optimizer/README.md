# 探索用サブエージェントの制御

既存のDSHの `spawn` プロバイダーを利用する、任意導入のコード実装です。
`rdsh_explore` は、履歴を引き継がない短い探索依頼に適しています。
自己完結した依頼と、必要なファイルの場所を渡してください。
元の `subagent` や `subagent_fork` は、別の用途として利用できます。

標準設定は、同時実行2件、待機8件、待機期限10秒、出力上限4096トークン、深さ1、依頼サイズ64 KiBです。
親や依頼で指定されたトークンや深さの上限がより小さい場合は、そちらを優先します。
同じ親からの実行中の重複依頼は拒否します。完了または破棄された後であれば、同じ依頼を再実行できます。
結果のキャッシュや自動再試行機能はありません。

エージェントの作成、モデルの選択、権限、出力スキーマ、ツールの制限、破棄はDSHが担当します。
モデルは親または依頼側の選択を維持します。安価なモデルへの自動切り替えは行いません。
待機中に親のモデル、作業場所、委譲権限の設定が変更された場合は、実行を拒否します。
実行枠はネイティブ側の破棄が完了するまで保持し、破棄に失敗した場合でも新しい実行で埋めることはしません。
バックグラウンドでの継続、会話履歴のコピー、プロンプトの切り詰めには対応していません。

対応APIは `@deepseek-ai/dsh-subagent` / `dsh-tool-subagent` **0.2.0-rc.2** と **0.2.1-alpha.2**です。
両方の公開パッケージにおいて、ネイティブヘルパー、ツール、UIスロットとの契約テストを通過しています。
Desktop SDKのCIでは、同梱されている0.2.1-alpha.2との契約を3 OSで検証します。
同じバージョンの標準 `spawn` プロバイダーを有効にしてください。
対応していないプロバイダーへは実行を転送しません。

```sh
PROFILE=desktop SUBAGENTS=1 ./plugins/install.sh
# Web profile:
PROFILE=web SUBAGENTS=1 ./plugins/install.sh
# deterministic tests, no model or authentication calls:
node --test plugins/rdsh-subagent-optimizer/test/*.test.mjs
```

Desktopでは、アプリのプラグイン画面からこのディレクトリを追加することもできます。
プラグインの設定で上限を変更できます。実際の費用や応答時間の改善率は測定していません。
